# MoonUp 输入协议（WASM 交互版）

本文档定义 `lib/wasm_api` 导出的 `moonup_run(input)` 文本协议：**10 行文本（`\n` 分隔）**，多值字段用 **`;;`** 分隔。该协议同时是演示页「试试引擎」区与任何外部宿主（CLI / Web / IM 机器人）接入的统一入口。

## 协议总览

| 行 | 字段 | 含义 | 格式 |
|---|------|------|------|
| 1 | `objective` | O 目标：要达成什么 | 单值 |
| 2 | `gap` | G 差距：当前卡在哪 | 单值 |
| 3 | `situation` | S 情境：发生了什么 | 单值 |
| 4 | `move` | M 下一步：打算怎么做 | 单值 |
| 5 | `facts` | 事实：已发生、可验证 | 多值 `;;` |
| 6 | `feelings` | 感受：主观情绪 | 多值 `;;` |
| 7 | `missing_context` | 缺失上下文：未知信息 | 多值 `;;` |
| 8 | `evidence` | 证据：来源 + 描述 | `kind\|描述`，多值 `;;` |
| 9 | `features` | 场景路由特征 | 多值 `;;` |
| 10 | `missing_evidence` | 缺失信息：证据不足处 | 多值 `;;` |

行数不足 10 时缺失行按空处理（对应段输出「待补充」，不编造）；超出的行被忽略。空行不影响解析。

## 证据来源 kind（第 8 行）

| kind | 含义 | 权重 |
|------|------|------|
| `written` | 书面承诺（邮件 / 文档 / 签字） | 高（w=3） |
| `resource` | 资源分配（预算 / 人员 / 工具） | 高（w=3） |
| `oral` | 单次口头承诺 | 低（w=1） |
| `guess` | 用户猜测 / 推断 | 低（w=1） |

未知 kind 回退为 `guess`。描述为空则该条证据被丢弃。

## 输入示例

```
把口头承诺转化为可验证条件
新责任出现但授权、资源、评估标准都不清
老板承诺机会但未明确时间线、资源支持与晋升标准
将承诺转化为书面条件清单
老板在会上口头让我负责新项目;;没有给我预算和人员
很委屈，又要背锅
不知道成功怎么评估
written|邮件确认了新项目范围;;resource|给了预算但没给人力;;oral|会上口头说会考虑晋升;;guess|我感觉他在故意拖延
口头承诺晋升;;两个领导要求冲突
晋升评估标准;;预算审批人
```

> 演示页会自动把输入中的中文分号 `；`/`;` 归一为 `;;`；直接调用协议时请使用半角 `;;`。

## 输出结构

输出为一段文本，顺序为：

1. **管线摘要**：`清洗(四元组=true) → 证据(置信度=High) → 路由(场景) → 护栏(N条触发) → 假设(N条) → 案例(N条) → 报告(12段)`
2. **缺失信息**：本次输入未覆盖的信息清单
3. **安全边界**：内置护栏条数（当前 7 条）
4. **12 段结构化报告**（`## N. 段落标题` 格式）：OGS-M 情境清洗 / 认知定位 / 假设空间 / 双面与环境解读 / 用户状态与韧性校准 / 证据与置信度 / 相关案例参考 / 专业动作 / 第三选项 / 建议动作 / 脚本 / 下一步观察

## 浏览器调用（JS 示例）

```js
const bytes = await (await fetch('moonup.wasm')).arrayBuffer();
const { instance } = await WebAssembly.instantiate(
  bytes, {},
  { builtins: ['js-string'], importedStringConstants: '_' }
);
const out = instance.exports.moonup_run(inputText); // 10 行文本
```

要求 Chromium 131+（js-string builtins）；`moonup.wasm` 由 `moon build --release --target wasm-gc` 产出（34 KB），输入不离开浏览器。

## 与 main.mbt 结构化调用的对应

`moon run main` 使用 MoonBit 原生结构（`@ogsm.Ogsm::new` / `@evidence.EvidenceItem::new` 等）驱动同一管线；`moonup_run` 只是同一管线的文本协议封装，两者共享 7 个模块与全部推理规则，输出结构一致（确定性：同一输入恒得同一输出）。
